# 全栈成长规划 / Fullstack Growth Roadmap

> 从前端工程师成长为全栈工程师的系统性路径规划。

---

## 1. 为什么需要规划

公司对你的预期是**快速成长为可靠的全栈工程师**。这意味着：

- 不再局限于写页面、调 API
- 需要理解完整的请求生命周期
- 能够独立完成从前端到后端到数据处理的完整功能
- 最终能够独立负责某个业务模块的全栈开发

---

## 2. 成长阶段划分

```
第一阶段（1-2个月）│ 站稳后端基础
第二阶段（3-4个月）│ 深入业务核心
第三阶段（5-6个月）│ 独立负责模块
```

---

## 3. 第一阶段：站稳后端基础

### 3.1 目标

- 能读懂 Go 代码
- 能独立完成简单的 API 开发
- 理解数据库操作

### 3.2 重点任务

| 任务 | 时间 | 衡量标准 |
|------|------|----------|
| Go 语法过关 | 第1周 | 能读懂 `api-go` 中的简单 handler |
| GORM  CRUD | 第2周 | 能独立写一个简单的增删改查 API |
| Gin 路由和中间件 | 第2-3周 | 能给 API 添加一个新路由 |
| JWT 认证流程 | 第3周 | 理解请求从进入 Gin 到查询数据库的完整流程 |
| 独立完成一个小功能 | 第4-8周 | 从设计到实现到上线，独立完成 |

### 3.3 关键代码位置

- `apps/api-go/internal/handler/` - API 处理器
- `apps/api-go/internal/model/` - 数据模型
- `apps/api-go/internal/middleware/` - 中间件

### 3.4 检查清单

- [ ] 能写一个简单的 Go handler
- [ ] 能用 GORM 完成一次数据库查询
- [ ] 能在 Gin 中添加一个新的路由
- [ ] 能描述 JWT token 的验证流程
- [ ] **完成一个小功能（推荐从简单的增删改查开始）**

## 4. 第二阶段：深入业务核心

### 4.1 目标

- 理解 Temporal 工作流
- 能够编写 Activity 和 Workflow
- 理解多个 AI 供应商的对接模式

### 4.2 重点任务

| 任务 | 时间 | 衡量标准 |
|------|------|----------|
| 理解 Temporal 核心概念 | 第9周 | 能向他人解释 Workflow 和 Activity 的区别 |
| 编写第一个 Activity | 第10-11周 | 能写一个对接新 AI 供应商的 Activity |
| 编写第一个 Workflow | 第12-14周 | 能编排一个包含多个 Activity 的 Workflow |
| 理解 SSE 推送机制 | 第15周 | 能解释视频生成进度是如何推送到前端的 |
| 参与视频处理模块开发 | 第16周 | 能独立处理视频相关的 bug |

### 4.3 关键代码位置

- `apps/worker-go/` - Temporal Worker 和 Workflow 定义
- `apps/video-service/` - 视频处理微服务

### 4.4 检查清单

- [ ] 能独立编写一个 Activity
- [ ] 能编排一个简单的 Workflow
- [ ] 知道项目的 Workflow 是如何被触发的
- [ ] 理解 SSE 如何配合工作流实现进度推送
- [ ] **能独立完成一个 AI 供应商的对接**

## 5. 第三阶段：独立负责模块

### 5.1 目标

- 能够独立负责完整的业务模块
- 理解系统间的协作关系
- 能够做技术方案设计和权衡

### 5.2 重点任务

| 任务 | 时间 | 衡量标准 |
|------|------|----------|
| 独立负责一个完整功能 | 第17-20周 | 从设计到上线独立完成 |
| 理解微服务间通信 | 第21周 | 知道 api-go 和 video-service 如何交互 |
| 数据库设计与优化 | 第22周 | 能设计简单的数据表结构 |
| 性能调优经验 | 第23-24周 | 有过一次实际调优经验 |

### 5.3 检查清单

- [ ] 独立完成过至少一个完整功能
- [ ] 能画出系统间的数据流图
- [ ] 能设计简单的数据表
- [ ] 有过性能调优的经验
- [ ] **能够在 code review 中提出有价值的建议**

## 6. 日常学习方法

### 6.1 代码学习

1. **每天**阅读 `api-go` 或 `worker-go` 的代码 30 分钟
2. 遇到不懂的 Go 语法，记录并查阅文档
3. 尝试用自己的话复述代码逻辑

### 6.2 实践优先

- 争取每次有后端任务时主动参与
- 不要等别人分配，主动问"有什么可以帮忙的"
- 每次 bug 都是学习机会，尝试从前端到后端全链路理解

### 6.3 文档积累

- 每理解一个模块，写一篇简短的笔记
- 用自己的话解释，而不是抄文档
- 定期更新本文档的检查清单

## 9. 心态建议

1. **不要怕问问题** - 问问题是最高效的学习方式
2. **不要等完全准备好再动手** - 在项目中学习是最好的方式
3. **接受成长中的挫折** - 初期看不懂代码是正常的
4. **主动争取机会** - 想成长就不能被动等待
5. **建立知识体系** - 零散的知识点需要系统化才能内化

---

> 记住：团队对你的预期是快速成长。这不是建议，而是要求。保持主动，保持饥渴。
