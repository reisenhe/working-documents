# 全栈成长规划 / Fullstack Growth Roadmap

> 以**复杂度**和**覆盖面**为维度的里程碑式规划，配合 AI 工具加速学习。

---

## 0. 核心思路

### 学习策略

1. **AI 辅助编程** - 让 AI 帮你写代码，你来做 Code Review 和理解
2. **小步快跑** - 每个里程碑都要有可运行的结果
3. **家校合一** - 在公司学和在家做项目相互印证
4. **复杂度递进** - 从 CRUD → 外接服务 → 异步编排 → 完整系统

### 最终目标

在家搭建一个**与团队架构类似**的完整系统，验证学习成果：

```
前端 (Vue)
  ↓
Go API (Gin + JWT)
  ↓
任务队列 (Temporal)
  ↓
AI 供应商 / 视频处理
```

---

## M1: Minimal Go API

### 目标

能跑起来一个最简单的 Go API：增删改查。

### 技能要求

- Go 基础语法
- Gin 路由
- GORM  CRUD

### 验收标准

```bash
# 启动服务
go run main.go

# 测试
curl http://localhost:8080/products
curl -X POST http://localhost:8080/products -d '{"name":"test","price":99}'
curl http://localhost:8080/products/1
curl -X PUT http://localhost:8080/products/1 -d '{"price":88}'
curl -X DELETE http://localhost:8080/products/1
```

### 家校对应

| 公司项目 | 家里练习 |
|----------|----------|
| `api-go` | 用同样的结构写一个精简版 |

---

## M2: 加认证

### 目标

在 M1 基础上加上 JWT 认证。

### 技能要求

- JWT 中间件
- 登录/注册接口
- Token 验证流程

### 验收标准

```
1. 未带 Token 请求 → 401
2. 带正确 Token   → 200 + 数据
3. Token 过期     → 401
```

### 家校对应

| 公司项目 | 家里练习 |
|----------|----------|
| JWT 中间件在哪实现的 | 在你的精简版实现同样逻辑 |

---

## M3: 接一个 AI 供应商

### 目标

调用一个外部 AI API，理解什么叫"外部服务对接"。

### 技能要求

- HTTP 客户端（Go 的 net/http 或 ai-sdk）
- API 调用、响应解析、错误处理
- 环境变量管理（API Key）

### 验收标准

```
1. 调用 AI 供应商 API 成功返回结果
2. 能处理 API 错误（超时、限流、invalid key）
3. 把 API Key 放在环境变量，不硬编码
```

### 家校对应

| 公司项目 | 家里练习 |
|----------|----------|
| 豆包/可灵/海螺 等 | 用一个免费供应商练手（如 OpenAI compatible API） |

---

## M4: 异步任务入门

### 目标

理解什么叫"异步任务"，为什么不能同步等 AI 返回。

### 技能要求

- 简单的任务队列概念（先用内存队列理解）
- 任务状态：pending → processing → done/failed
- 任务 ID + 查询接口

### 验收标准

```
1. POST /tasks 立即返回 task_id，实际处理在后台
2. GET /tasks/:id 返回当前状态
3. 不带 Token 时任务不被接受
```

### 家校对应

| 公司项目 | 家里练习 |
|----------|----------|
| Temporal Worker | 先用 Go channels/goroutine 实现简单队列 |

---

## M5: 进度推送

### 目标

理解 SSE（Server-Sent Events），实现服务器向浏览器推送进度。

### 技能要求

- SSE 协议（与 WebSocket 的区别）
- Gin 中实现 SSE 端点
- 前端 EventSource 接收

### 验收标准

```
1. 前端页面显示实时进度条
2. SSE 连接在任务完成后正确关闭
3. SSE 端点也需要 Token 验证
```

### 家校对应

| 公司项目 | 家里练习 |
|----------|----------|
| 视频生成进度推送 | 在你的任务系统上实现同样的 SSE 推送 |

---

## M6: 视频处理

### 目标

理解 FFmpeg 命令行调用，实现视频转码/截图。

### 技能要求

- FFmpeg 常用命令
- Go 执行外部命令（os/exec）
- 文件上传、存储、返回

### 验收标准

```
1. 上传视频 → FFmpeg 转码 → 返回处理后文件
2. 能截取视频某一帧作为缩略图
3. 处理大文件不阻塞主服务（异步）
```

### 家校对应

| 公司项目 | 家里练习 |
|----------|----------|
| `video-service` | 用 Node.js + Fastify 实现（你熟悉的） |

---

## M7: 完整工作流

### 目标

把 M3-M6 串联起来：用户请求 → AI 生成 → 视频处理 → SSE 推送。

### 技能要求

- Temporal Workflow 编排
- Activity 的设计（单一职责）
- 重试策略、超时控制

### 验收标准

```
1. 发起一个视频生成任务
2. 后台：调用 AI → 获取结果 → 视频处理 → 更新状态
3. SSE 实时推送每一步进度
4. 中途失败自动重试（配置重试策略）
```

### 家校对应

| 公司项目 | 家里练习 |
|----------|----------|
| `worker-go` 里的 Workflow | 这时候你应该能看懂并照着实现类似的 |

---

## M8: 在家搭建迷你版

### 目标

整合所有里程碑，搭建一个与公司架构类似的完整系统。

### 最终架构

```
前端 (Vue SPA)
    ↓ axios
Go API (Gin + JWT)
    ↓ Temporal Client
任务系统 ( Temporal Server)
    ↓ Execute
Worker (AI 调用 + 视频处理)
    ↓ SSE
前端实时展示进度
```

### 验收标准

```
1. 能通过前端发起一个"视频生成"任务
2. 看到实时进度推送
3. 任务完成后能查看/下载结果
4. 代码结构与公司项目类似
```

## 9. 日常学习方法

### 9.1 代码学习

1. **每天**阅读 `api-go` 或 `worker-go` 的代码 30 分钟
2. 遇到不懂的 Go 语法，记录并查阅文档
3. 尝试用自己的话复述代码逻辑

### 9.2 实践优先

- 争取每次有后端任务时主动参与
- 不要等别人分配，主动问"有什么可以帮忙的"
- 每次 bug 都是学习机会，尝试从前端到后端全链路理解

### 9.3 文档积累

- 每理解一个模块，写一篇简短的笔记
- 用自己的话解释，而不是抄文档
- 定期更新里程碑检查清单

## 10. AI 工具使用建议

### Prompts 模板

```
# 学习 Go 语法
"我用 Go 写了一个 handler，帮我看看有没有问题：..."
"Go 里怎么实现 xxx（对比 Node.js 的 yyy）"

# 学习 Temporal
"帮我用 Temporal Go SDK 写一个 Activity，功能是..."
"一个 Workflow 包含两个 Activity，怎么写？"

# 学习 FFmpeg
"用 Go 执行 FFmpeg 缩放视频的命令是什么？"
"FFmpeg 常用命令：截取帧、转码、加水印"
```

### 原则

1. **不要复制粘贴** - 先理解 AI 给的代码，再自己敲
2. **问为什么** - "为什么这里要用 channel 而不是..."
3. **看错误信息** - 把编译错误贴给 AI，它会帮你修

## 11. 心态

- **每个里程碑都要有产出** - 不是一个"学完了"的里程碑，是"能用起来了"
- **优先理解，再深入** - 先知道整体怎么跑，再研究细节
- **家是试验场** - 公司的代码不能动，家里可以随便造
- **有问题就问 AI** - 不要卡在某个点太久，AI 是你的 24 小时导师
